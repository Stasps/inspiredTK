# О чем документ
Здесь описана структура состояния сервера (аналог сейв-файла для многопользовательской игры): снимки состояния симуляции.
Формат снапшотов - JSON. Оперативное хранение - реляционное (предварительно PostgreSQL, см. архитектурный документ). Это два физических представления одной логической модели: схема БД и JSON-снаппшот описывают одни и те же сущности и должны изменяться синхронно.

Нейронки могут изменять структуру только после ревью и аппрува от человека.

## Обязательные правила формата

- **version** - поле версии формата в шапке каждого снапшота. Обязательно с первой версии. Механика миграций между версиями - открытый вопрос, отсутствие поля - нет
- **Метаданные снапшота**: серверный таймстамп снятия, номер тика на момент снятия - без них восстановление после краша и дельта при переподключении не определены
- **Только целые числа или десятичные строки фиксированной точности** для всех количественных значений (ресурсы, провиант, курсы маркета, время). Никаких float: сериализация и арифметика float недетерминированы на уровне реализации, а симуляция обязана быть детерминированной. Ресурсы - в мелких единицах (например, ×1000 базовой единицы)
- **Серверное время** - единственное игровое время; в состоянии хранятся серверные таймстампы

## Верхнеуровневые сущности (черновик, ждёт проектирования)

- **player**: аккаунт, герой, настройки (боевые окна)
- **village**: здания и уровни, склады (две категории - продовольственный/непродовольственный, зафиксировано в [[game-design]], «Склады»), войска
- **map cell**: координаты, месторождения, занятость
- **npc camp/village**: лагеря и деревни варваров, рост
- **march**: движущиеся войска (отправление, прибытие, провиант)
- **market rates**: курсы NPC-маркетмейкера
- **kingdom**: королевство, сокровищница, дипломатия (позже)
- **event log**: журнал критичных событий (бои, транзакции, дипломатические действия). Дополняет снапшоты: события между снапшотами не должны теряться при краше. Требование из архитектурного документа («снапшоты + журнал критичных событий»)

## Открытые вопросы

- Схема БД vs JSON-снаппшоты: что храним реляционно, что документами (граница между двумя представлениями одной модели, не два конкурирующих варианта)
- Версионирование формата состояния (миграции между версиями) - механика, поле version при этом обязательно уже сейчас
- Что входит в снимок сезона и как фиксируется его результат
- Что входит в переподключенческий снапшот игрока: полный мир невозможен, нужно определить видимую область (правило из сетевых правил архитектурного документа: снапшот + дельта за время обрыва)
- Состав event log: какие события критичны и не восстановимы из состояния, а какие выводимы
