# О чем документ
Реестр id всех сущностей, которым нужен идентификатор в конфигах, коде и сейве. Названия для игрока - в [[game-design]], структура состояния - в [[save-structure]]. Новую сущность сначала записываем сюда, потом в код.
Статус: черновик на проверку человеком. Ничего здесь не [Зафиксировано], пока не одобрено.

## Правила
- id на английском, `snake_case`, только `a-z`, цифры и `_`.
- id не зависит от названия для игрока: переименование в [[game-design]] меняет только текст, id остаётся.
- id уникален внутри своей категории, не переиспользуется после удаления сущности.
- Отображаемые имена хранятся в локализации по ключу `<категория>.<id>`, а не в конфигах логики.
- Статические id (ресурсы, здания, юниты и т. д.) задаются в конфигах. Динамические (игроки, поселения, марши) имеют вид `<префикс><число>`, например `p1`, `s1`.

Вопрос к человеку: в roadmap:30 поля добычи названы «Разборка/Сортировка/Металлобаза/Теплица», а в game-design это «Руины/Свалка пластика/Свалка металлолома/Теплица». Какие названия верные? id выше даны по game-design.

## Типы клеток карты
Клетки адресуются координатами (x, y), собственного id не имеют (static, см. [[save-structure]], map cell).
| id | Название |
| --- | --- |
| `settleable` | заселяемая клетка |
| `outpost` | аванпост |
| `bunker_site` | площадка бункера |
| `marauder_camp` | лагерь мародёров |
| `marauder_settlement` | поселение мародёров |

Тип аванпоста задаётся ресурсом из таблицы «Ресурсы» и размером бонуса, отдельных id не требуется. Раскладка ресурсных полей клетки: `layout_<mats>_<plastic>_<scrap>_<food>`, например `layout_4_4_4_6`.
