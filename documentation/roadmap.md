# О чем документ
План разработки игры Inspired Kingdoms. Все задачи ведутся через этот план; вне этого плана задач не существует. Системы и числа - в [[game-design]].
Два раздела задач: **«Ранняя альфа»** (рабочий прототип, полностью играбельный) и **«Планы на будущее»** (контент после выпуска альфы).

## agent-tasks

### Ранняя альфа (рабочий прототип)
Цель: полностью играбельная версия - полный сезонный раунд: поселение → город → аванпосты → альянсы → Центр Связи → итог сезона. Механики 1:1 из Travian Kingdoms (см. [[game-design]], «Принцип ранней альфы»).

**Сервер (сделано):**
- [x] Проектный каркас: конфиги, валидация, слои (Data/Logic/Storage)
- [x] Карта 101×101, система координат -50..50, центр (0,0)
- [x] Поселение: здания, 4 ресурса, ленивое производство
- [x] Войска: пехотинец, марши, провиант
- [x] Сохранение: JSON-снапшоты + журнал событий
- [x] Тесты логики

**Сервер (сделать):**

- [ ] Жетоны и местная валюта: конвертация, NPC-торговец

**Архитектура:**
- [x] Продумать масштабирование broadcast при росте онлайна: решено, рассылка адресная (см. [[architecture]], «Конкурентная модель»)
- Обработка команд: один актор симуляции (горутина-владелец мира), select по очереди команд и таймеру ближайшего события планировщика (min-heap); тикера нет
- Рассылка состояния: адресная - игрок получает только своё состояние при его изменении и ответы на свои команды; карта по запросу области; broadcast всем убран
- Очередь команд: FIFO, общий буфер 1024-2048, не больше 4 команд одного игрока в очереди; переполнение - отказ `server_busy` отправителю; лимит частоты на игрока - отказ `rate_limited`
- Время: событийно-ориентированная модель (Compute on Read + планировщик)
- [x] Решить модель времени и конкурентности: один актор симуляции + планировщик событий + акторы-сессии игроков, без глобального тика; нагрузка 100 стабильно / 1000 пик (см. [[architecture]], «Конкурентная модель»)
- [x] Реализовать планировщик: min-heap и таймер ближайшего события вместо тика 1 с в main.go; убрать `Engine.Tick` и `World.Tick`
- [x] Акторы-сессии: горутины чтения и записи на соединение (один писатель на сокет, отправка из симуляции не блокирует), вход игрока по `?player=<id>` без авторизации (в debugMode незнакомый игрок создаётся), приветствие `hello` с поселениями, команды от игрока сессии с `settlementId` и проверкой владения. Временно: исходящая очередь 32 с разрывом при переполнении, JSON состояния собирается в горутине симуляции (уйдёт с адресной рассылкой)
- [ ] Реализовать транспорт под модель: адресная рассылка, ответы с `cmd_id`, пределы очередей. Заодно убрать временную рассылку состояния всем раз в секунду (`pushTick` в main.go) и научить клиент интерполировать ресурсы и прогресс
