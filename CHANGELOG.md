# Changelog

## [0.0.5] - 2026-11-10

**Добавлено**:
- SPA-архитектура: одна страница, роутинг через hash (#main / #map), без перезагрузки.
- Цветовые темы: 3 варианта (Природа, Минимализм, Песок), переключатель в шапке, сохранение в localStorage.
- Производство ресурсов в час: отображение в шапке под текущим количеством.
- Здание "Склад" (warehouse): 3 уровня, вместимость 1000/2000/3000.
- Поле `Capacity` в конфиге зданий.
- Ленивая загрузка карты: запрос только при первом показе.
- Кэширование данных карты: 30 секунд, не перерисовывать без изменений.
- DocumentFragment в renderMap: оптимизация отрисовки.

**Изменено**:
- Система координат: от -50 до 50, центр (0,0), игрок появляется в центре.
- `mapSize` в конфиге: 101 (нечётное число для центра).
- `World.CellAt`: работа с логическими координатами -50..50.
- Карта отцентрирована на (0,0), показывает отрицательные координаты.
- Удалён `client/map.html` — весь функционал в `index.html`.

**Исправлено**:
- Переход между страницами без новой вкладки.
- WebSocket не переподключается при смене страницы.

**Технические детали**:
- `clientState` в `state.go`: обёртка мира с состоянием деревни.
- `productionRate()`: базовое производство 10/час + бонусы зданий.
- `lastMapRequestAt`, `MAP_CACHE_TTL_MS`: кэширование запросов карты.
- `renderMap.lastRendered`: защита от повторной отрисовки тех же данных.

**Известные ограничения**:
- Клиентская валидация кнопок не реализована (disabled при нехватке ресурсов).
- Статический файловый сервер не добавлен (открытие через file:///).

## [0.0.4] - 2026-11-10

**Добавлено**:
- Визуальное отображение прогресса строительства: прогресс-бар, название здания, целевой уровень, оставшееся время.
- Визуальное отображение прогресса тренировки: количество юнитов в очереди, время до следующего.
- Отображение серверного времени в шапке клиента (вместо номера тика).
- Кнопка закрытия карты (toggle).
- Поле `StartUnix` в `domain.BuildJob` — точка начала строительства для расчёта прогресса.

**Изменено**:
- `client/index.html`: прогресс-бары, серверное время, закрытие карты, улучшенная структура.
- `domain.BuildJob`: добавлено поле `StartUnix`.
- Архитектура времени: отказ от тиковой модели в пользу событийно-ориентированной с ленивыми вычислениями (Compute on Read + планировщик событий).

**Технические детали**:
- Прогресс строительства: `(now - startUnix) / (finishUnix - startUnix) * 100%`.
- Серверное время передаётся в `VillageState.ServerTimeUnix`, клиент использует его для расчётов.
- `SkipTime` сдвигает все таймеры мира: стройка, тренировка, марши, планировщик варваров.

**Известные ограничения**:
- `TrainUnits` принимает `unitType`, но внутри всегда тренирует `infantry` — при добавлении типов юнитов станет багом.
- Broadcast шлёт весь `World` каждый тик — для 1-10 игроков приемлемо, при росте нужны диффы.

## [0.0.3] - 2026-11-09

**Добавлено**:
- Реальные методы `sim.Engine`: `AddResources`, `UpgradeBuilding`, `TrainUnits`, `GetMap` — команды теперь выполняют действия, не заглушки.
- Авто-создание debug-игрока при старте с пустым миром.
- Команда `get_map` — возвращает карту мира (10000 клеток: деревни, лагеря, месторождения).
- Команда `add_resources` — чит-код для debug-режима (только при `debugMode: true`).

**Изменено**:
- `testMode` переименовано в `debugMode` везде: `config.go`, `construction.go`, `world.json`.
- `executeCommand` в `main.go` — все заглушки заменены реальными вызовами методов Engine.
- Базовая выработка ресурсов: +10/час каждой деревней, даже без зданий.
- Лимит хранилища: 3000 непродовольственных, 1000 продовольственных.
- **Архитектура времени**: отказ от тиковой модели в пользу событийно-ориентированной с ленивыми вычислениями.
  - Ресурсы не тикают: вычисляются по формуле `rate * (now - last_update)` в момент чтения (Compute on Read).
  - «Жёсткие» события (завершение стройки, прибытие марша, окончание найма) — в планировщике (min-heap по `fire_at`).
  - Периодический тик отсутствует; проверка просроченных событий — раз в 500 мс или по таймеру ближайшего события.

**Исправлено**:
- 4 теста, падавшие из-за изменённых значений в `world.json` (вместимость складов, базовая выработка).

**Технические детали**:
- `AddResources` проверяет `DebugMode`, добавляет ресурсы с учётом лимита склада.
- `UpgradeBuilding` проверяет ресурсы, списывает, повышает уровень.
- `TrainUnits` проверяет казарму, ресурсы, добавляет в `StationedInfantry`.
- `GetMap` возвращает `[]MapCell` с типами: empty, village, camp, deposit.
- `architecture.md`: обновлено описание Game Logic слоя, добавлена конкурентная модель (actor-модель, запрет глобального мьютекса, планировщик).
- `save-structure.md`: добавлены `last_update_at` для ленивого пересчёта, `scheduled_event` для планировщика, убрано поле `tick` из метаданных снапшота.

**Известные ограничения**:
- `TrainUnits` принимает `unitType`, но внутри всегда тренирует `infantry` — при добавлении типов юнитов станет багом.
- Broadcast шлёт весь `World` каждый тик — для 1-10 игроков приемлемо, при росте нужны диффы.

## [0.0.2] - 2026-11-09

**Добавлено**:
- WebSocket-транспорт на `:8080/ws` — приём команд от клиентов, broadcast состояния всем подключённым.
- Очередь команд `chan Command` (буфер 100, FIFO) — WS-обработчик кладёт команды, главный цикл `main.go` забирает и исполняет.
- Debug HTML-клиент `client/index.html` — подключение по WebSocket, отображение состояния (ресурсы, здания, армия, тик), кнопки команд.
- Зависимость `gorilla/websocket v1.5.3` в `server/go.mod`.

**Технические детали**:
- Интерфейс `EngineInterface` удалён из `transport/ws.go` — сервер не трогает движок напрямую, только складывает команды в канал.
- Переполнение очереди: `select` с `default` — команда отклоняется с ошибкой `command queue full`, без блокировки.
- `BroadcastState(state)` рассылает состояние всем клиентам; мьютекс только на список клиентов, не на мир.
- Невалидные данные команды отклоняются сразу с поясняющей ошибкой клиенту.
- В `main.go` добавлен `case cmd := <-wsServer.CommandChan()` в главный `select` — вызов `executeCommand` только из этого цикла, движок потокобезопасно не трогается.
- `executeCommand` маршрутизирует `upgrade_building` / `train_unit` / `finish_now` с валидацией параметров; методы движка пока возвращают `not implemented` (заглушки).
- Клиент читает состояние из первой деревни: `resourcesMilli / 1000`, `buildings` как map ключ-уровень, `stationedInfantry`.
- HTTP-сервер запускается в горутине, не блокирует тик симуляции.

**Проверка**:
- `go build ./cmd/server` и `go vet ./...` — чисто.
- Тестовый WS-клиент подключился к `:8080/ws`, команды `upgrade_building` и `finish_now` дошли до главного цикла (в логе `command ... failed: not implemented` — заглушки работают).
- Состояние `{"type":"state","data":{"tick":19,...}}` приходит каждый тик всем подключённым.
- Переполнение очереди и невалидные данные возвращают `{"type":"error",...}` без блокировки.

**Известные ограничения**:
- Команды пока не выполняют реальных действий — нет методов в `sim.Engine` (заглушки).
- Начальное состояние приходит с первым тиком (в течение 1 сек после подключения).
- Broadcast шлёт весь `World` целиком (карта 100×100 на каждый тик) — для 1-10 игроков debug-режима приемлемо, при росте стоит слать снапшот только при изменениях или диффы.

## [0.0.1] - 2026-11-07

**Добавлено**:
- Проектный каркас: структура папок, конфиги (ресурсы, здания, юнит, бой), валидация конфигов при старте.
- Карта 100×100: генерация месторождений, размещение стартовой деревни игрока.
- Деревня: 6 зданий, 4 ресурса, производство по серверному времени.
- Войска: пехотинец, марши, провиант, отмена марша.
- Бой: формула атака/защита, модификаторы 1.5/3.0, потери.
- PvE: 5-10 статичных лагерей варваров, атака раз в 24 часа в окна игрока.
- Тестовый режим "завершить немедленно".
- Сохранение состояния: периодические JSON-снапшоты по `save-structure`.
- Headless-тесты логики (бой, производство, марши).

**Технические детали**:
- Engine не потокобезопасен: все вызовы только из одной горутины (актор мира с почтовым ящиком команд).
- Состояние только в памяти запрещено: снапшоты раз в N минут + журнал критичных событий.
- Глобальный мьютекс на мир запрещён как архитектурный костыль.

**Известные ограничения**:
- Нет клиентского транспорта — сервер headless, нечем играть.
- Нет аутентификации.
